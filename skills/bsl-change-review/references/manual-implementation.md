# Режим `manual-implementation`

Эта инструкция применяется только после выбора режима ручной реализации.
Общие границы, источники и доказательность заданы в `../SKILL.md`.

## Требуемый результат

Подготовь самодостаточную инструкцию для человека, который вручную изменит
конфигурацию. Не используй diff-маркеры внутри копируемых BSL-блоков.

Для каждого изменения существующего BSL обязательна пара:

1. `Найти` — дословный текущий блок.
2. `Заменить целиком на` — полный новый компилируемый блок.

Для вставки укажи дословный уникальный якорь, положение до/после него и
ожидаемое число совпадений. Для новой процедуры покажи её целиком. Если
корректный блок невозможен, поставь конкретному изменению `blocked` и назови
недостающий код или контракт. Не завершай результат одним резюме.

## Метаданные и форма

Для каждого нового или изменяемого реквизита укажи точный уровень, имя,
синоним, тип, длину или разрядность/точность, составной тип и квалификаторы,
обязательность, значение по умолчанию, назначение и места использования.

Для элемента формы укажи имя, вид, родителя, путь к данным, заголовок,
положение и обработчики событий. Непрочитанные свойства не угадывай: ставь
`unknown` и называй ручную проверку в Конфигураторе.

Строки модуля — только ориентир. Основной идентификатор места — точный адрес и
дословный блок или якорь.

## Самопроверка режима

- Каждый блок `Найти` дословно присутствует в повторно прочитанном коде.
- Каждый `Заменить` полон, не содержит `+`, `-` или placeholder и следует
  подтверждённым контрактам API.
- Для непроверенного количества якорей указано `unknown`; слепая замена всех
  совпадений запрещена.
- Все реквизиты и элементы либо подтверждены, либо явно создаются инструкцией.
- Порядок не использует сущность до её создания.
- Для каждого изменения существующего BSL есть пара блоков либо `blocked`.
- Указаны проверки успешного и ошибочного сценариев и обратимый откат.
- Инструкция понятна без истории чата и не заявляет компиляцию/runtime без
  фактического запуска.
