# 1C Form Creator

Версия: `0.2.0-candidate`. Локальный skill для файловых выгрузок управляемых форм 1С. Компилятор и checker входят в каталог skill; Python-пакет и MCP-сервер не нужны. Для комплекта объекта вместе с формой установи рядом `1c-metadata-creator`. Инструкция не обещает поддержку каждого вида формы: если локальный компилятор не представляет нужную структуру, сохрани исходник и сообщи `blocked` с точной причиной.

## Порядок работы

1. Прочитай `references/workflow.md`. Для разработки BSL с файлами и платформенными API прочитай также `references/acceptance.md`. Если нужны список выбора или динамические колонки таблицы, открой `references/schema-patterns.md`.
2. Найди `Configuration.xml`, существующие XML/BSL формы и примеры в **той же** выгрузке. Выясни формат XML, владельца формы, тип формы и версию платформы. Для встроенной обработки `Обработка.*` с новой формой используй `--auto-data-processor`; за основу можно взять `templates/data-processor-form.json`. Для других объектов подготовь полный metadata specification или изменяй существующую форму без регистрации нового владельца.
   Для основной формы одного элемента справочника выбирай `context.role=object`
   и главный реквизит `Объект` типа `metadata_object`; `role=list` даёт
   таблицу всех элементов и не заменяет объектную форму.
   При отдельной сборке формы нового объекта сначала запусти `build` без
   `--config`, затем зарегистрируй объект через `1c-metadata-creator build
   --config`; один `form_creator.py build --config` без metadata specification
   регистрацию не выполняет.
3. Собери specification формы и BSL-модуль в отдельных файлах. Не составляй 1С XML вручную. Используй `scripts/form_creator.py build` в **пустой временный каталог**. Скрипт выдаёт канонические owner-relative XML/BSL с UTF-8 BOM и CRLF, проверяет структуру и создаёт отдельную копию `Configuration.xml` с патчем, если передан `--config`.
4. Проверь комплект `validate`. Проверь BSL API по справке нужной версии и нативный импорт в Конфигураторе/EDT, открытие формы и поведение, если такая среда доступна. Записывай эти уровни отдельно: `static_passed` означает только статическую проверку.
5. Переноси артефакты в рабочую выгрузку только после просмотра diff, сохраняя остальные объекты и связанные файлы. Если пользователь дал доступ к тестовой конфигурации, применяй изменения в ней; для иных баз нужен отдельный доступ. При неудаче не оставляй частично заменённый комплект.

## Быстрый вызов

```bash
python3 skills/1c-form-creator/scripts/form_creator.py inspect --config /path/to/config
python3 skills/1c-form-creator/scripts/form_creator.py build --spec /tmp/form.json --module /tmp/Module.bsl --auto-data-processor --config /path/to/config --output /tmp/form-build
python3 skills/1c-form-creator/scripts/form_creator.py validate --form-xml /tmp/form-build/DataProcessors/Имя/Forms/Форма/Ext/Form.xml --module /tmp/form-build/DataProcessors/Имя/Forms/Форма/Ext/Form/Module.bsl --owner Обработка.Имя --role object --form-name Форма --bundle /tmp/form-build --format-version 2.20
```

`--bundle` указывает на корень результата `build`; не клади туда черновой `Module.bsl` или другие `.xml`/`.bsl`. Подробный пример — в workflow. Возвращаемые статусы: `static_passed`, `failed`; выход 2 при ошибке. Вывод `verification.json` содержит также `bsl_api`, `native_import`, `runtime_visual`, `business_behavior` со значением `not_checked` до отдельной проверки.

## Границы

- `extract` применяй для изменения существующей формы только при точном round-trip. Если он отказал, правь с нативным инструментом 1С и повторно валидируй; не переписывай форму из неполной specification.
- Скрипт не исполняет BSL, не читает XLSX и не заменяет компиляцию в 1С. Код чтения файла, события и пользовательские команды разрабатывает агент, сверяя имена и сигнатуры API по платформенной справке. Кодировка относится к текстовому CSV/TXT, не к XLSX.
- Не копируй содержимое конфигураций, реальные данные, секреты и BSL в удалённый MCP без необходимости. Локальный скрипт не выполняет сетевых запросов и не меняет входную конфигурацию.
- При отсутствии нативной среды укажи `native_import: not_checked` и передай человеку точные действия для проверки. Не называй комплект работающим до загрузки, открытия формы и проверки сценария.

## Установка и удаление

Скопируй каталог `1c-form-creator` целиком в каталог skills клиента. Для `--metadata-spec`, `--auto-data-processor` и проверки `--bundle` скопируй рядом `1c-metadata-creator`. Для Codex CLI проверено размещение `$CODEX_HOME/skills/1c-form-creator`; произвольный `skills/` репозитория сам по себе не обнаруживается. Для клиента без поддержки skills передай `SKILL.md` и файлы `references/`. Обновление — замена каталога версией из совместимого checkout `mcp-1c`. Удаление — удаление установленного каталога skill; созданные им файлы конфигурации отдельно не удаляются. Результаты слепых прогонов и границы кандидата записаны в `skills/README.md`.
