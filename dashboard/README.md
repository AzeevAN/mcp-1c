# Дашборд MCP-1C

Современный интерфейс — React SPA поверх HTTP API того же процесса, в котором
работают MCP и `Registry`. Отдельного backend, отдельного тома данных и второго
набора прав у интерфейса нет.

## Запуск готового образа

Пользовательский запуск использует один файл [`compose.yaml`](../compose.yaml)
и готовый образ:

```bash
cp .env.example .env
# Задайте разные API_TOKEN и ADMIN_TOKEN длиной не меньше 32 символов.
docker compose config --quiet
docker compose up -d
```

`MCP1C_DASHBOARD=on` включает SPA и является значением по умолчанию.
`MCP1C_DASHBOARD=off` не регистрирует ни страницы, ни `/api/v1/*`; MCP и
`/health` продолжают работать. Других режимов нет.

`MCP1C_ACCESS=local` доверяет только прямому HTTP origin. Значение
`https-proxy` предназначено для явно настроенного внешнего HTTPS reverse proxy;
сам proxy в Compose не входит. Порт хоста в обоих случаях остаётся привязан к
`127.0.0.1`.

Официальный Docker-запуск требует оба токена. Они должны быть различными,
печатными ASCII-строками без пробелов длиной не меньше 32 символов. Токен
чтения открывает MCP и страницы; административный дополнительно разрешает
загрузку, удаление, разбор входящих выгрузок, изменение словаря и управляемый
перезапуск.

## Локальная разработка frontend

```bash
cd dashboard
npm ci
npm test -- --run
npm run typecheck
npm run build
```

Vite складывает результат в `dashboard/dist/`. После изменения frontend
синхронизируйте точную пакетную копию и проверьте её:

```bash
cd ..
.venv/bin/python tools/sync_dashboard_assets.py
.venv/bin/python tools/sync_dashboard_assets.py --check
```

`src/mcp1c/dashboard_dist/` входит в wheel и sdist, поэтому установленный
Python-пакет раздаёт SPA без рабочей копии репозитория и без Node.js. Docker
кладёт тот же production build в тот же пакетный путь. Для клиентских путей
(`/sources`, `/queries`, `/reference`, `/graph`, `/roles`, `/dictionary`, `/object`,
`/syntax`, `/login`) backend возвращает один `index.html`.

Локальный образ собирается тем же target, что релизный:

```bash
python3 tools/build_image.py mcp1c:local
MCP1C_IMAGE=mcp1c:local docker compose up -d
```

Скрипт принимает только чистый Git HEAD и передаёт Docker его архив, поэтому
локальные данные, `.env`, секреты и ignored-файлы в production-образ не входят.

## Контракт API

Основные read-only ручки:

- `GET /api/v1/dashboard/bootstrap` — версия, права, auth и сводные счётчики;
- `GET /api/v1/sources` — источники и покрытия;
- `GET|POST /api/v1/queries` — параметры и прогон поисковых фраз;
- `GET /api/v1/cards/object`, `/api/v1/cards/syntax` — карточки;
- `GET /api/v1/graph` — окрестность и серверная раскладка;
- `GET /api/v1/roles` — конфигурации и страница descriptor ролей;
- `GET /api/v1/roles/find` — роли-кандидаты по объекту и операциям;
- `GET /api/v1/roles/access` — страница объявленных прав одной роли;
- `GET /api/v1/roles/restriction` — ограниченное окно явно выбранного RLS;
- `GET /api/v1/dictionary` — встроенный и локальный слои словаря;
- `GET /api/v1/reference*` — статус, поиск и карточки общей справки.

Административные ручки находятся под `/api/v1/sources/*`,
`/api/v1/dictionary/*`, `/api/v1/reference/*` и
`/api/v1/server/restart`. Они требуют административный токен или
административную cookie-сессию. Запрос с cookie дополнительно проходит
same-origin проверку `Origin`/`Referer`; явный заголовок токена не использует
браузерные полномочия.

`POST /login` обменивает токен на `HttpOnly; SameSite=Strict` cookie. Для HTTPS
cookie получает `Secure`. `POST /logout` удаляет серверную сессию и cookie.
Сессии хранятся только в памяти процесса и исчезают при перезапуске.

## Два вида ZIP

`СтруктураКонфигурации_*.zip` — компактная schema v1 из обработки проекта; её
можно передать через «Загрузить источник». Большой архив команды
**Конфигуратор → Конфигурация → Выгрузить конфигурацию в файлы… → Архив**
содержит структуру, модули, формы и роли. Его можно принять до 500 МиБ через
блок «Полная файловая выгрузка», положить в `data/incoming/` либо открыть из
заранее настроенного read-only источника. Browser-upload блока вызывает
`POST /api/v1/sources/intake/upload`. SPA показывает все найденные варианты без
автоматического выбора, запускает server-side progress и выводит послойный
semantic preview. Candidate и preview сами ничего не публикуют: активное
поколение меняется только после отдельной кнопки подтверждения, которая
вызывает `POST /api/v1/sources/intake/confirm`. Готовый preview переживает
обновление страницы и рестарт. Расширение без родительской конфигурации не
предлагает действий и не публикуется.

## Роли и объявленные права

Маршрут `/roles` открывается из основной навигации без обязательного `config`
в URL. При нескольких конфигурациях пользователь выбирает нужную в интерфейсе.
Страница имеет два режима: «роль → доступы» и «объект → роли». Descriptor
ролей, права и кандидаты приходят серверными страницами; большая роль не
загружается и не рисуется целиком. Следующая страница заменяет текущий список
прав, а каталог ролей дочитывается отдельно.

SPA ничего не вычисляет о доступе самостоятельно: HTTP и MCP используют один
`RoleAccessIndex` и resolver. UI различает explicit false, безусловный true и
условный RLS, показывает generation и SHA snapshot и прямо предупреждает, что
это объявленные права, а не эффективный доступ пользователя. Полный текст RLS
не входит в обычный ответ и раскрывается только отдельной кнопкой; endpoint
`GET /api/v1/roles/restriction` возвращает окно до 8 000 символов и курсор без
необратимого обрезания.

`missing`, `error` и пустой Registry объясняются отдельно и не блокируют
остальные страницы. Все четыре role-endpoint read-only и требуют обычный
`API_TOKEN`; операций назначения или изменения ролей в интерфейсе нет.

## Границы

- SPA не читает `data/` напрямую: все снимки и мутации проходят через общий
  backend и `Registry`.
- Загрузка ограничена 500 МиБ и одним `file`-part; превышение останавливается
  во время multipart-разбора.
- Имена и пути из запросов сверяются с серверным разрешённым набором.
- Разбор, обход файлов и тяжёлые операции выполняются вне event loop.
- При `off` интерфейс и его API отсутствуют, а не маскируются пустой страницей.
