# Skills для разработки на 1С

Каталог содержит готовые инструкции и локальные инструменты для работы с BSL,
управляемыми формами и объектами метаданных. Все перечисленные skills проверены
и доступны для использования. Они распространяются вместе с проектом по
лицензии Apache-2.0.

## Доступные skills

| Skill | Версия | Назначение | Требования |
|---|---|---|---|
| [`bslfmt`](bslfmt/SKILL.md) | `0.2.0` | Форматирование BSL-файла или полного текста процедуры/функции с просмотром diff. Комментарии сохраняются; `-sbc` применяется только по просьбе удалить их. | Локальный `bslfmt`, Python 3.10+. |
| [`bsl-change-review`](bsl-change-review/SKILL.md) | `0.3.0` | Визуальное ревью изменений или инструкция ручного внесения BSL, форм и метаданных, включая бинарные формы. | Текущий код; для проверки API — справка целевой версии платформы через `mcp-1c`. |
| [`1c-form-creator`](1c-form-creator/SKILL.md) | `0.2.0` | Создание, изменение и проверка управляемой формы: `Form.xml`, `Module.bsl`, комплект встроенной обработки и регистрационный патч. | Python 3.12+; для комплекта объекта нужен соседний `1c-metadata-creator`. |
| [`1c-metadata-creator`](1c-metadata-creator/SKILL.md) | `0.1.0` | Сборка и проверка объекта метаданных с формой или без неё в файловой выгрузке конфигурации. | Python 3.12+ и соседний `1c-form-creator`. |

Создание форм и метаданных выполняется локально. Скрипты содержат собственные
компиляторы и проверки, сохраняют UTF-8 BOM и CRLF и записывают результат в
заданный каталог. Поддерживаемые структуры и команды описаны в каждом skill.
Проверка созданного комплекта в целевой версии 1С остаётся частью работы:
проверенная инструкция не заменяет компиляцию и запуск конкретного BSL-кода.

## Установка и обновление

Скачайте выбранный каталог целиком, включая `SKILL.md`, `references/`,
`scripts/` и `templates/`, если они есть. Подключите его средствами своего
клиента. Для создания объектов с формами установите рядом оба каталога:
`1c-form-creator` и `1c-metadata-creator`.

Для Codex каталоги размещаются в `$CODEX_HOME/skills/`; при стандартном
расположении — в `~/.codex/skills/`. Например:

```text
~/.codex/skills/
  bslfmt/
  bsl-change-review/
  1c-form-creator/
  1c-metadata-creator/
```

Клиенту без поддержки skills передайте `SKILL.md` и указанные в нём файлы
инструкций. Для `bsl-change-review` нужен reference выбранного режима.
Локальные скрипты запускаются агентом с доступом к нужной файловой выгрузке.

Для обновления замените установленный каталог целиком. Связанные skills для
форм и метаданных обновляйте из одной версии репозитория. Удаление каталога
отключает skill; созданные им файлы конфигурации сохраняются.

Установка и обновление самого форматтера описаны в
[`bslfmt/SKILL.md`](bslfmt/SKILL.md).

## Связь с MCP

Skills подключаются к клиентскому агенту отдельно от MCP-сервера. Сервер не
устанавливает их и не добавляет инструкции в `initialize` или `tools/list`.
Каталог не включается в Docker-образ или Python-пакет `mcp-1c`.

MCP предоставляет справку платформы и чтение конфигураций. Форматирование,
сборка XML/BSL и применение изменений выполняются локальными инструментами
в пределах задачи пользователя. Инструкции не расширяют права доступа агента.

## Публичность и лицензия

В каталог не входят данные внедрений, выгрузки конфигураций, производные
индексы, закрытые адреса, секреты и материалы фирмы «1С», на распространение
которых проект не имеет прав. Примеры используют обезличенные имена и пути.

При изменении возможностей skill обновляются его инструкция, этот каталог,
основной [README](../README.md) и [CHANGELOG](../CHANGELOG.md).
