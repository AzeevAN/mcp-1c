# Обработка выгрузки структуры конфигурации 1С

Готовит архив со структурой конфигурации в формате
[schema v1](../docs/schema-v1.md) для загрузки в MCP-сервер.

Тексты модулей конфигурации сюда **не попадают** — платформа не даёт к ним
доступа из встроенного языка. Индекс процедур строится отдельно, из выгрузки
конфигурации в файлы. То же касается предопределённых элементов на платформах
до 8.3.6. Разделение зафиксировано в [docs/data-sources.md](../docs/data-sources.md).

## Что собрано

| Файл в `dist/` | Форма | Формат | Платформа |
|---|---|---|---|
| `ОбычнаяФорма_XML.bsl` | обычная | XML | **8.3.5** и выше |
| `УправляемаяФорма_XML.bsl` | управляемая | XML | **8.3.5** и выше |
| `ОбычнаяФорма_JSON.bsl` | обычная | JSON | 8.3.6 и выше |
| `УправляемаяФорма_XML_JSON.bsl` | управляемая | XML и JSON на выбор | 8.3.6 и выше |

Выбор варианта: **версия платформы** решает формат, **режим приложения
конфигурации** — вид формы.

Типы `ЗаписьJSON`, `ПараметрыЗаписиJSON`, `ПереносСтрокJSON` и процедура
`ЗаписатьJSON` появились в 8.3.6. На 8.3.5 обращение к ним рвёт **компиляцию**
всего модуля, а не выполнение — поэтому в XML-вариантах их нет вообще, ни в
коде, ни в комментариях. Это проверяется при каждой сборке: `build_modules.py`
завершается с ошибкой, если в XML-варианте нашлось хоть одно упоминание JSON.

Рядом лежат две **собранные обработки** — их не надо ставить руками, можно
открыть сразу:

| Файл в `dist/` | Форма | Формат | Платформа | Что внутри |
|---|---|---|---|---|
| `ВыгрузкаСтруктурыКонфигурации_ОбычнаяФорма_XML.epf` | обычная | XML | **8.3.5** и выше | `ОбычнаяФорма_XML.bsl` плюс обработчик `ПриОткрытии` |
| `ВыгрузкаСтруктурыКонфигурации_УправляемаяФорма_XML_JSON.epf` | управляемая | XML и JSON на выбор | 8.3.6 и выше | `УправляемаяФорма_XML_JSON.bsl` |

Сверено по составу процедур и живым запуском: в XML-варианте обращений к
`ЗаписьJSON`/`ЗаписатьJSON` нет ни одного; собранная обычная EPF открылась и
сделала полную schema v1 выгрузку на платформе 8.3.5.1570.

Обработки собираются **в конфигураторе руками**, а не `build_modules.py`, и в
этом их отличие от остального `dist/`. Правка идёт прежним путём: `src/` →
сборка → вставка текста в модуль формы → сохранить `.epf`. Собранный файл
обновлять тем же коммитом, что и модуль, иначе он разойдётся с `dist/*.bsl`
молча.

Ядро обхода метаданных общее для всех четырёх — живёт в `src/core.bsl`
в единственном экземпляре. Код, требующий 8.3.6, размечен блоками
`// {{#json}} … // {{/json}}` и вырезается сборщиком.

## Сборка

```bash
python3 exporter-1c/build_modules.py
```

Сборщик сначала формирует и проверяет все четыре BSL-варианта, записывает их
во временный каталог рядом с `dist/` и только затем публикует каждый файл через
атомарную замену. Если не найден исходник или маркер, не пройдена проверка
совместимости с 8.3.5, не удалась временная запись либо публикация, прежний
набор остаётся на месте; уже заменённые файлы при сбое публикации откатываются.
Два собранных вручную `.epf` сборщик не трогает.

Правки вносить **только в `src/`**, файлы BSL в `dist/` перезаписываются.

## Установка в конфигурацию

1. Конфигуратор → Внешняя обработка → создать новую.
2. Создать форму нужного вида (обычную или управляемую).
3. Добавить реквизиты формы:

   | Реквизит | Тип | По умолчанию | Смысл |
   |---|---|---|---|
   | `РазмерЧанка` | Число | 500 | объектов на файл, `0` — без разбиения |
   | `ЛимитОбъектов` | Число | 0 | объектов каждого вида, `0` — все |
   | `ФорматВыгрузки` | Строка(10) | — | только для `УправляемаяФорма_XML_JSON`, поле выбора |

4. Вставить в модуль формы текст соответствующего файла из `dist/`.
5. Добавить на форму кнопку/команду `ВыгрузитьСтруктуру`.
6. Для управляемой формы — назначить обработчик события формы
   `ПриСозданииНаСервере`.
7. Сохранить как `.epf`.

Обработку, собранную на 8.3.5, можно открывать на старших платформах.
Обратное неверно — для парка со старой платформой собирайте на 8.3.5.

## Использование

1. Открыть обработку в нужной информационной базе.
2. `ЛимитОбъектов = 0` — это обязательно для рабочей выгрузки. Ненулевое
   значение — тестовый режим, в манифест пишется `truncated="true"`,
   и загрузчик откажется заливать такую выгрузку без явного подтверждения.
3. Нажать «Выгрузить», выбрать путь к ZIP.

Результат:

```
СтруктураКонфигурации_УправлениеТорговлей_2026-08-13.zip
├── manifest.xml
└── objects/
    ├── catalog.001.xml
    ├── document.001.xml
    └── ...
```

Каждый файл чанка несёт тот же конверт, что описан в schema v1:
`schema_version`, `type`, номер `chunk` и точный `count`. `count` заранее
ограничивается размером чанка и `ЛимитОбъектов`, поэтому совпадает с записью в
манифесте и в XML-, и в JSON-варианте.

## Проверить на своей платформе

Всё, что может отсутствовать на конкретной версии, обёрнуто в `Попытка` —
выгрузка не прервётся, просто соответствующей секции не будет. После первой
выгрузки на **8.3.5** стоит убедиться, что в файлах есть:

- [x] `predefined_available` в манифесте. На **8.3.5 проверено: `true`** —
      `ОбъектМетаданных.ПолучитьИменаПредопределенных()` доступен; в живой
      обезличенной проверке получены 283 имени у 33 объектов. Ранняя гипотеза
      о недоступности до 8.3.6 опровергнута; подробности и резервный запрос —
      в [docs/data-sources.md](../docs/data-sources.md)
- [ ] `definedtype` среди файлов — коллекция `Метаданные.ОпределяемыеТипы`
- [ ] `movements` у документов — коллекция `Объект.Движения`
- [ ] `indexing` у реквизитов — свойство `Индексирование`
- [ ] сигнатура `ЗаписьJSON.ОткрытьФайл(Имя, Кодировка, ДобавлятьBOM, Параметры)`
      — только для JSON-вариантов, на 8.3.6 порядок параметров стоит сверить

Быстрая проверка целостности готового архива:

```bash
unzip -l СтруктураКонфигурации_*.zip | head -30
unzip -p СтруктураКонфигурации_*.zip manifest.xml | head -20
```

## Расширение

**Добавить вид метаданных** — одна строка в `КоллекцииМетаданных()`
плюс, если у вида есть своя специфика, ветка в `ДополнитьСвойствамиВида()`
и `ДополнитьСоставомВида()`.

**Добавить поле объекта** — вставка в соответствующую `Структуру`.
Сериализаторы формат-агностичны, XML и JSON подхватят поле сами.
Новое необязательное поле версию схемы не повышает.
