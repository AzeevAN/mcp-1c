# Типовые намерения поиска процедур

`search_procedures` умеет распознать ограниченный набор расширенных русских
формулировок о стандартных событиях 1С и перевести их в точное имя процедуры.
Например, запрос «что выполняется при записи объекта» распознаётся как
`ПриЗаписи`, а «где формируются движения документа при проведении» — как
`ОбработкаПроведения`.

Это не универсальное понимание произвольного кода. Слой предназначен только
для типовых имён, одинаковых в конфигурациях, и намеренно отказывается от
догадки при отсутствии уверенного единственного варианта.

## Какие события входят

Встроенный каталог содержит 12 имён:

- `ОбработкаПроверкиЗаполнения`;
- `ОбработкаПроведения`;
- `ПередЗаписью`;
- `ПриЗаписи`;
- `ОбработкаУдаленияПроведения`;
- `ОбработкаЗаполнения`;
- `ПриОткрытии`;
- `ПередОткрытием`;
- `ПриСозданииНаСервере`;
- `ПриЗакрытии`;
- `ОбработкаВыбора`;
- `ОбработкаОповещения`.

Фразы и маркеры лежат в
`src/mcp1c/standard_procedure_intents.py`. Это встроенное знание о платформе:
оно меняется через git, ревью и обезличенный набор
`tests/queries/standard-procedure-intents.json`, а не через дашборд. Локальные
имена и соглашения конкретного внедрения в этот каталог не добавляются.

## Как выбирается результат

Распознаватель возвращает только каноническое имя. Реализации ищутся в уже
готовом полном оглавлении модулей, включая неэкспортные процедуры; отдельного
поискового индекса, дискового кэша, состояния пользователя или сессии нет.

- Без `scope` ответ сообщает распознанное имя и число реализаций, но не
  выбирает адрес. Нужно повторить запрос с объектом, модулем или формой.
- Если внутри `scope` найдена одна реализация, ответ содержит её точный адрес
  и сигнатуру.
- Если внутри объекта осталось несколько реализаций, адрес не выбирается:
  нужен точный модуль или форма в `scope`.
- Если намерение не распознано, без изменений работает обычный точный и
  полнотекстовый поиск `search_procedures`.
- Точное каноническое имя (`ПриЗаписи`) сохраняет прежний режим и может
  вернуть несколько реализаций с учётом `limit`.

Такой контракт защищает от наиболее опасного исхода: похожая естественная
фраза не должна незаметно превратиться в случайную одноимённую процедуру из
другого объекта.

## Границы

Пользовательская процедура с произвольным именем ищется прежним способом: по
точному имени либо по словам имени и комментария-шапки экспортной процедуры.
Типовой каталог не обучается из запросов, не собирает сессионные
последовательности и не принимает правила через административный интерфейс.

Новое типовое событие или формулировка добавляются только тогда, когда они
верны для всех конфигураций. Вместе с правилом нужен обезличенный
положительный пример, близкие отрицательные запросы и полный прогон обычного
поиска: улучшение типовых фраз не должно перехватывать пользовательские.

## Замер

Спайк 2026-08-25 воспроизводится из корня проекта:

```bash
PYTHONPATH=src .venv/bin/python \
  tools/lab/measure_standard_procedure_intents.py --data data
```

На зафиксированном наборе распознаны 59 из 60 положительных фраз и 35 из 36
замороженных holdout-примеров; все 30 контрольных фраз отклонены. На доступной
типовой конфигурации каталог правил вместе с нормализованным поиском занимал
около 10 КиБ достижимого состояния. Отдельный индекс продуктовому варианту не
нужен: он использует уже загруженное оглавление процедур.
