# Повторяющиеся элементы формы

Эти фрагменты подтверждены локальной schema v2 и статической сборкой на XML 2.20. Перед применением к иной версии сверяй контракт checkout; успешная сборка не заменяет импорт в 1С.

## Список выбора кодировки

В `attributes[]` нужен строковый реквизит, например `{"name":"Кодировка","type":{"kind":"string","length":20}}`. Элемент формы связывается с ним так:

```json
{"kind":"input_field","name":"КодировкаПоле","data_path":"Кодировка","choice_list":[
  {"value":"UTF-8","presentation":{"ru":"UTF-8"}},
  {"value":"Windows-1251","presentation":{"ru":"Windows-1251"}}
],"list_choice_mode":true}
```

`choice_list` принимает объекты `{value, presentation}`, не строки. Числовой реквизит задаётся как `{"kind":"number","digits":3,"fraction_digits":0,"allowed_sign":"nonnegative"}`; ключи `precision`/`scale` этой схемой не принимаются.

## Дополнительная колонка таблицы формы

Если атрибут имеет `type.kind=value_table`, его значение в модуле формы — `ДанныеФормыКоллекция`. У неё нет свойства `Колонки`. На сервере создай вложенный `РеквизитФормы` с путём к атрибуту таблицы, вызови `ИзменитьРеквизиты`, затем добавь дочерний `ПолеФормы` в элемент таблицы и задай `ПутьКДанным` вида `ТаблицаДанных.<Имя>`. Сигнатуры и доступность всех вызовов проверь по справке целевой платформы; итоговое отображение — только нативным запуском.

## Чтение CSV

Для явной кодировки `ЧтениеТекста.Открыть` принимает имя файла и кодировку; проверь точную сигнатуру и клиентский контекст по версии платформы. Не закрывай читатель перед `Продолжить` внутри цикла строк: следующая итерация обратится к закрытому файлу. Закрывай его после цикла и на выходах из функции. Если нужна поддержка веб-клиента, отдельно проверь доступность `ЧтениеТекста` и путь передачи файла на сервер.
