# Режим `review`

Эта инструкция применяется только после выбора режима `review`. Общие границы,
источники и доказательность заданы в `../SKILL.md`.

## Требуемый результат

Для BSL покажи человеку точный текущий и предлагаемый код как читаемый unified
diff. Для каждого логического изменения кода:

1. Сохрани несколько дословных неизменённых строк контекста.
2. Пометь удаляемые строки `-`, добавляемые `+`.
3. Объясни наблюдаемое изменение поведения.
4. Назови риск и поведение при ошибке.

Если частей несколько, покажи каждую. Частичный diff явно назови частичным.
Diff предназначен для ревью и не обязан быть удобен для прямого копирования.

Если предложение меняет реквизиты, элементы формы или свойства метаданных,
покажи их отдельной таблицей «Сейчас / Предлагается» с точным владельцем,
действием, типом и квалификаторами либо свойствами формы. Не изображай такие
изменения как BSL-diff. Непрочитанное текущее значение пометь `unknown` и не
называй добавление или изменение доказанным.

## Формат Markdown

Используй структуру без рекламных и общих разделов:

````markdown
# Предложение изменения BSL

## Контекст

- Задача: ...
- Конфигурация: ...
- Расширение: ...
- Объект: ...
- Модуль: ...
- Процедура: ...
- Источник текущего кода: ...
- Идентификатор снимка: ...
- Платформа: ...
- Статус предложения: только ревью, не применено

## Краткий итог

Что меняется и что намеренно не входит в предложение.

## Изменение 1 — краткое название

```diff
 неизменённая строка контекста
-удаляемая строка
+добавляемая строка
 неизменённая строка контекста
```

**Почему:** ...

**Поведение при ошибке:** ...

## Изменения формы и метаданных

| Владелец и свойство | Сейчас | Предлагается | Причина |
|---|---|---|---|
| ... | ... | ... | ... |

Не добавляй раздел, если форма и метаданные не меняются.

## Нерешённые части задачи

- ... — `unknown`, `not_checked` или `blocked` с причиной.

## Проверки

| Проверка | Состояние | Доказательство или причина |
|---|---|---|
| Текущий код прочитан | `confirmed` | ... |
| Актуальность исходника | ... | ... |
| BSL API и сигнатуры | ... | ... |
| Целевая версия платформы | ... | ... |
| Компиляция | `not_checked` | ... |
| Runtime | `not_checked` | ... |

## Применение

Изменение не применялось. Необходимые owner-gates и проверки перед применением.
````

## Отдельный `.diff`

При MCP-only источнике показывай diff только в Markdown: тело процедуры не
является физическим файлом и не даёт надёжных абсолютных диапазонов модуля.

Создавай `change-review.diff` только если пользователь явно запросил файл и
текущий код прочитан из локального физического файла. Строй его обычным
diff-инструментом. Обязательны `---`, `+++` и числовые hunk-диапазоны вида
`@@ -12,4 +12,5 @@`. Если доступен Git, проверь разбор командой
`git apply --numstat change-review.diff`; это не доказывает применимость к 1С.

В Markdown и diff сохраняй реальные табуляцию, переводы строк и кавычки; не
заменяй их буквальными `\t`, `\n` или `\"`.

## Критерии готовности

- Человек видит точный diff, а не пересказ.
- Каждое место имеет точный адрес и дословный контекст.
- Изменения формы и метаданных имеют отдельное сравнение текущих и предлагаемых
  значений; неподтверждённое текущее состояние помечено `unknown`.
- Текущее и предлагаемое поведение разделены.
- Новые API проверены либо явно помечены `not_checked`.
- Вызов через переменную имеет доказанный тип либо `unknown`.
- Отдельный `.diff` не создан по MCP-окну процедуры.
- Созданный `.diff` имеет числовые hunk-заголовки и проверен parser либо
  помечен `not_checked`.
- Утверждения о ветках ошибок учитывают фактический порядок вызовов.
- Результат понятен без истории чата и не заявляет непройденные проверки.
