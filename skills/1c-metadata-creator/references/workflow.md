# Specification и комплект метаданных

Поддержаны `Справочник`, `Документ`, `РегистрСведений`, встроенные `Обработка` и `Отчет`. Версия схемы — 1; `format_version` должен совпадать с корнем `Configuration.xml` (например, `2.20`). `identity` — UUID объекта. Компилятор детерминированно выводит из него UUID дочерних элементов.

Минимальный справочник без формы:

```json
{
  "schema_version": 1,
  "object_ref": "Справочник.НовыйСправочник",
  "format_version": "2.20",
  "identity": "40000000-0000-0000-0000-000000000001",
  "synonym": "Новый справочник",
  "code_length": 9,
  "description_length": 150,
  "attributes": [],
  "forms": []
}
```

Атрибут: `{"name":"Артикул","synonym":"Артикул","type":{"kind":"string","length":50}}`. Типы: `string` (`length` 1..1024), `boolean`, `number` (`digits`, `fraction_digits`), `date` (`fractions`: `date`, `time`, `date_time`), `catalog_ref`/`document_ref` (`object`). Полная закрытая схема находится в `scripts/metadata_core/schema.py`, ограничения и проверки — в соседних `compiler.py` и `checker.py`.

Для объекта с формой добавь запись в `forms` после локальной сборки формы. `form_xml_file` и `module_bsl_file` являются удобными файловыми входами CLI и заменяются точным содержимым до вызова компилятора:

Для справочника, когда задача просит основную форму просмотра или редактирования
элемента, укажи `role=object`, `default=true` и форму с главным
`metadata_object` реквизитом `Объект`. Поля используют `Объект.Code`,
`Объект.Description`, `Объект.<ИмяРеквизита>`. Сценарий таблицы всех элементов
справочника — отдельная `role=list` и `DefaultListForm`; он не выполняет
требование основной формы элемента.

```json
{
  "name": "Форма",
  "synonym": "Основная форма",
  "role": "object",
  "default": true,
  "form_xml_file": "Form.xml",
  "module_bsl_file": "Module.bsl"
}
```

Если прикладного BSL нет, пустой локальный `Module.bsl` допустим только как вход
`module_bsl_file`: компилятор не включает пустой каркас в итоговый комплект.
Не копируй его вручную в выходной каталог. Для проверки итоговой формы передай
`form_creator.py validate` путь к `Form.xml` без `--module`; итоговый
`metadata_creator.py validate` проверяет весь комплект. Форма должна
принадлежать тому же `object_ref`, иметь ту же XML-версию и пройти проверку.
Сохраняй итоговый прикладной BSL, если он есть, не каркас с незаполненной
логикой. Возможные роли определяются видом объекта; компилятор проверяет их,
defaults и пути стандартных полей. Для отчёта компилятор также создаёт шаблон СКД.

В результате `build` лежат файлы владельца (`Catalogs/Имя.xml`, `DataProcessors/Имя/Forms/Форма/Ext/Form.xml` и т. д.), `verification.json`, а с `--config` также патч и копия `Configuration.xml`. Скрипт проверяет только структуру. После просмотра diff применяй файлы к выгрузке, загружай её в 1С и проверяй пользовательский сценарий. Сообщай отдельно `static`, `bsl_api`, `native_import`, `runtime_visual`, `business_behavior`; неизвестные результаты оставляй `not_checked`.
