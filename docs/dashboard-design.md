# Дашборд: дизайн и текущий контракт

Дашборд — React SPA внутри того же процесса, который обслуживает MCP и
`Registry`. Он включается значением `MCP1C_DASHBOARD=on` (по умолчанию) или
полностью отсутствует при `off`. Серверного HTML-интерфейса и второго
production-контейнера нет.

## Зачем

CLI остаётся полным административным интерфейсом, но для повседневной проверки
важны браузерные сценарии:

- увидеть согласованный снимок источников и покрытия;
- загрузить выгрузку и наблюдать фоновый разбор;
- разобрать подготовленный файл из `data/incoming/`;
- проверить живые поисковые формулировки;
- открыть карточки объекта и синтаксиса, граф связей и локальный словарь;
- проверить и заменить подписанную общую справку.

Дашборд не пишет промахи в репозиторий и не дублирует стенд `mcp1c.bench`.
Сервер может работать из готового образа без рабочей копии проекта.

## Архитектура

```text
server.py             /mcp, /health, /admin/reload и подключение UI
runtime_config.py     on/off, local/https-proxy и Docker auth contract
dashboard_runtime.py  /api/v1, login/logout и package-local SPA
dashboard_backend.py  auth, multipart, jobs, incoming и общие операции
dashboard/            React/Vite, состояние интерфейса и компоненты
dashboard_dist/       синхронная production-копия внутри Python-пакета
registry.py           единственный живой Registry
tools.py              предметные снимки и ответы MCP
```

По умолчанию backend читает SPA из `mcp1c/dashboard_dist` установленного
пакета. `MCP1C_DASHBOARD_DIST` остаётся явным seam для dev-сервера и тестов,
но официальный wheel, sdist и Docker image уже содержат одинаковые assets.
Node.js в runtime не требуется.

React не читает и не монтирует `data/`. Все операции проходят через API того
же Python-процесса. После успешной публикации источник сразу видят MCP и SPA;
второго Registry и обязательной ручной перезагрузки нет.

Состояние вкладки и состояние работы различаются. Клиент хранит навигацию,
выбор и локальные предпочтения. Ход разбора, ошибки и готовность источника
принадлежат серверу и восстанавливаются из его снимка после обновления страницы.

## Общая справка в меню источников

На странице «Источники» общая справка занимает отдельную секцию под списком
общих источников. Длинный список прокручивается над ней. Строка показывает
состояние и число материалов, если API его возвращает; по нажатию открывается
окно сведений и загрузки `.mcp1cref`. В пустом состоянии сразу виден выбор файла.
Большой административной плашки внизу страницы нет; форма ZIP/HBK/JSON
направляет пользователя к боковой секции для загрузки общей справки.

Окно показывает ожидание перезапуска отдельно от активного снимка. Удаление
доступно через «Дополнительные действия» с прежним точным подтверждением.
Подтверждения удаления и рестарта заменяют содержимое одного окна. Escape
возвращает к сведениям или закрывает окно с возвратом фокуса в меню; во время
загрузки/удаления/перезапуска закрытие заблокировано. Фоновая страница inert.
Режим только чтения получает публичный статус без административного API;
внешний путь отключает загрузку и удаление из окна.

## Режимы запуска

| Переменная | Значение | Результат |
|---|---|---|
| `MCP1C_DASHBOARD` | `on` | JSON API и SPA зарегистрированы |
| `MCP1C_DASHBOARD` | `off` | UI и `/api/v1/*` отвечают 404; MCP и health работают |
| `MCP1C_ACCESS` | `local` | forwarded-заголовки не считаются доверенными |
| `MCP1C_ACCESS` | `https-proxy` | доверяется origin, восстановленный proxy headers |

Неизвестное или пустое значение останавливает запуск до bind порта. Внешний
HTTPS reverse proxy не входит в образ или Compose. Порт хоста в обоих режимах
остаётся на `127.0.0.1`.

## Маршруты

| Маршрут | Назначение | Доступ |
|---|---|---|
| `GET /api/v1/dashboard/bootstrap` | версия, права, auth, сводные счётчики | чтение |
| `GET /api/v1/sources` | согласованный снимок источников и покрытий | чтение |
| `GET /api/v1/sources/coverage` | текущий полный журнал корпуса | чтение |
| `GET /api/v1/sources/admin` | jobs, incoming и файлы вне Registry | администратор |
| `POST /api/v1/sources/*` | загрузка, разбор, очистка и точечное удаление | администратор |
| `GET|POST /api/v1/queries` | контракт формы и прогон фраз | чтение |
| `GET /api/v1/cards/object` | карточка объекта | чтение |
| `GET /api/v1/cards/syntax` | карточка синтаксиса | чтение |
| `GET /api/v1/graph` | окрестность и серверная раскладка | чтение |
| `GET /api/v1/dictionary` | эффективные правила словаря | чтение |
| `POST /api/v1/dictionary/*` | изменить локальный словарь | администратор |
| `GET /api/v1/reference*` | статус, поиск и карточка общей справки | чтение |
| `POST /api/v1/reference/*` | установить или удалить управляемый bundle | администратор |
| `POST /api/v1/server/restart` | управляемый restart после смены справки | администратор |
| `POST /login`, `POST /logout` | создать или закрыть серверную сессию | — |

Пути SPA (`/`, `/sources`, `/queries`, `/reference`, `/graph`, `/dictionary`,
`/object`, `/syntax`, `/login`) получают один `index.html`. `/assets/*`
разрешает только существующий файл внутри каталога assets и не допускает выход
путём наружу.

## Авторизация

`API_TOKEN` закрывает чтение MCP и данных дашборда. `ADMIN_TOKEN` дополнительно
разрешает мутации. Административный токен также годится для чтения.

`POST /login` сравнивает токены через `hmac.compare_digest`, сохраняет только
случайный идентификатор сессии и выдаёт cookie `HttpOnly; SameSite=Strict;
Path=/`. При HTTPS добавляется `Secure`. Сессии живут в памяти процесса и
исчезают при рестарте. `POST /logout` удаляет запись и cookie.

Мутация с cookie требует совпадения `Origin` или `Referer` с origin сервера.
Явный административный заголовок не использует браузерную cookie и не зависит
от этой CSRF-проверки. Значение `next` на странице входа принимается только как
внутренний путь.

Официальный Docker runtime запускается с обязательной проверкой обоих токенов:
каждый не короче 32 печатных ASCII-символов без пробелов, значения различны и
не являются известными placeholder. Bare Python-запуск сохраняет явный
локальный режим без обязательного `--require-tokens` для разработки и тестов.

## Загрузка, incoming и фоновые задания

- Multipart принимает один `file`-part и только известные поля.
- Общий предел загрузки — 500 МиБ; превышение прерывается во время разбора
  multipart, до запуска предметного обработчика.
- `.zip`, `.hbk` и `.json` идут в Registry; `.mcp1cref` имеет отдельный
  маршрут, предел и полный цикл проверки подписи.
- Клиентское имя сводится к последнему сегменту; удаление сверяется с точным
  серверным списком разрешённых файлов.
- Разбор, обход файлов, sha256, сохранение Registry и удаление больших корней
  выполняются вне event loop.
- Jobs хранят только оперативный статус. Завершённые записи можно очистить;
  активная работа при этом не исчезает.
- Файл в `incoming/` никогда не удаляется сервером. Слишком свежий файл
  считается ещё копирующимся; одновременно разбирается не более одного.

Registry публикует новое поколение атомарно. Ошибка остаётся в job и журнале,
но не подменяет прежний готовый источник.

## Поиск, карточки и граф

`POST /api/v1/queries` принимает строковые `config`, `scope` и список
`phrases`: не больше 32 непустых фраз по 4096 символов. На каждую возвращаются
первые пять видимых попаданий, до пяти скрытых версией, оценки, причины и
точные ссылки. Фильтрация синтаксиса использует версию выбранной конфигурации.

Карточки получают буквальный Markdown через `tools.get_object()` или
`tools.get_syntax()`. Общий `render_markdown()` сначала экранирует внешние
данные и только затем добавляет ограниченную разметку; frontend не вводит
второй Markdown parser.

Граф использует `graph_view.neighbourhood()`. Сервер возвращает узлы, рёбра,
направления, подписи, цвета, степени, координаты и границы `viewBox`. Frontend
только рисует и изменяет viewport. Допустимый предел нормализуется в диапазон
1…400, усечение называется явно.

## Словарь и общая справка

Снимок словаря показывает происхождение, область и возможность удаления.
Мутации проходят через `Registry.mutate_dictionary()`, поэтому сохраняются
атомарно и начинают действовать в новых запросах без пересборки индекса.
Встроенные правила через HTTP не меняются.

Подписанный `.mcp1cref` сначала полностью проверяется, затем атомарно заменяет
управляемый файл. Активный provider остаётся неизменяемым до рестарта. Внешний
путь дашборд не устанавливает и не удаляет. Restart не получает Docker socket:
при наличии supervisor сервер только завершает собственный процесс после
ответа, а внешний runtime поднимает его снова.

## Проверки

Backend-тесты используют голый `Starlette`, временные каталоги и синтетические
выгрузки. Проверяются права, cookie, CSRF, лимиты multipart, атомарность,
фоновые операции, JSON-контракты и отсутствие блокировки event loop.

Frontend проверяется отдельно:

```bash
cd dashboard
npm test -- --run
npm run typecheck
npm run build
```

Приёмка образа дополнительно запускает один image ID в четырёх сочетаниях
`on/off` × `local/https-proxy` и доказывает, что MCP не зависит от UI.
