# Дашборд: дизайн и текущее состояние

Первоначальный дизайн согласован 2026-08-16. Решением владельца от 2026-08-28
классический серверный HTML заморожен как переходный fallback, а новый
интерфейс развивается отдельным React/Vite-проектом. Документ сохраняет
исходные решения и фиксирует новую границу `off/classic/spa`.

Дашборд реализован в двух контурах: `classic` сохраняет весь прежний
функционал, включая фоновые задания и снимки /sources, а `spa` содержит
согласованный корень, обзор, навигацию, вход, управление источниками и
прогон поисковых формулировок, карточки, граф и управление локальным словарём.

## Зачем

Сейчас источник добавляется командой внутри контейнера:

```bash
docker compose exec mcp1c python -m mcp1c.cli reg-add /data/bootstrap/Выгрузка.zip --data /data
```

Это работает, но требует доступа к контейнеру и знания CLI. Дашборд закрывает
две вещи: **положить выгрузку через браузер** и **посмотреть, что сервер
отвечает на живую формулировку**, не поднимая консоль.

## Границы и текущее состояние

В первой версии появились:

- реестр загруженного с предупреждениями из манифестов;
- загрузка `.zip` и `.hbk` через браузер, удаление источника;
- прогон списка запросов с показом оценок и причин.

Позднее граница расширилась:

- словарь можно просматривать и править через `/dictionary`;
- загрузка и разбор идут в фоне, `/sources` показывает задания и атомарные
  состояния источников;
- появились карточки объекта и синтаксиса, граф связей и разбор файлов из
  `data/incoming/`.
- каждый готовый корпус кода получил три таблицы покрытия и один актуальный
  полный JSON-журнал в `data/logs/`.

Не реализована кнопка «записать промах в `tests/queries/`»: она меняла бы
рабочую копию репозитория, которой на сервере может не быть. Промахи остаются
воспроизводимыми наборами стенда.

Ожидаемый ответ рядом с запросом (как в `bench.py`) **сознательно не делаем**:
на десятке фраз попадание видно глазами, а массовый прогон с метриками уже
закрыт стендом из CLI. Дублировать его в браузере нечем оправдать.

## Архитектура

```
server.py             /mcp, /health, /admin/reload и выбранный UI-контур
dashboard_runtime.py  режим off/classic/spa и вход в /api/v1
dashboard.py          замороженный классический HTML
dashboard/            React/Vite, состояние интерфейса и визуальные компоненты
registry.py           единственный живой Registry, приём и состояния индексов
tools.py              общие снимки и предметные ответы
coverage_log.py       schema v1, атомарная запись и сверка identity
```

### Три режима

Переменная `MCP1C_DASHBOARD` принимает три значения:

| Значение | Что доступно |
|---|---|
| `off` | только MCP и служебные HTTP-маршруты, UI отсутствует; базовый Compose задаёт его явно |
| `classic` | прежний серверный HTML; fallback Python-запуска без переменной и явный Compose-override |
| `spa` | `/api/v1` и собранная React SPA вместо классических страниц |

Неизвестное значение останавливает запуск с понятной ошибкой. Молчаливого
fallback из `spa` в `classic` нет: оператор иначе считает, что проверяет новый
интерфейс, а на деле видит старый.

`dashboard_runtime.py` возвращает ровно один набор маршрутов:

```python
def routes(registry: Registry, *, mode: str | None = None) -> list[Route]: ...
```

`/mcp`, `/health` и `/admin/reload` в переключатель не входят. Поэтому режим
интерфейса не меняет состав инструментов и адрес MCP-клиентов.

### Один владелец данных

React не монтирует и не читает `data/`. Все чтения и записи проходят через
версионированный API того же Python-процесса, который обслуживает MCP. Поэтому
после успешной загрузки источник сразу видят агенты; второго Registry,
дублирования индексов и обязательного `/admin/reload` нет.

Состояние браузера и состояние задания различаются. Zustand хранит только
навигацию, выбранные элементы и локальные предпочтения. Ход разбора, ошибки и
готовность корпуса публикует сервер; перезагрузка вкладки не имеет права
выдать незавершённую серверную операцию за завершённую.

Первый предметный API не повторяет старую HTML-разметку. `tools.py` снимает
один согласованный снимок конфигураций и корпусов, а `dashboard_runtime.py`
только переводит его в JSON. Поэтому структура, основной код, расширения,
состояния и краткое покрытие не могут относиться к разным поколениям Registry.
Полный журнал читается отдельно и только после повторной проверки, что
`source_id` всё ещё обозначает текущий корпус кода.

### Отдельная разработка, один production-контейнер

В разработке Vite работает отдельно и проксирует `/api/v1` на тестовый MCP.
В production многоступенчатая сборка копирует только `dashboard/dist` в
расширенный Python-образ. Node и `node_modules` в runtime не попадают.
Базовая сборка не строит frontend и сохраняет нынешний размер и поведение.

Если позднее понадобится независимый выпуск UI, готовую SPA можно вынести в
статический контейнер без изменения API. Сейчас второй production-контейнер
добавил бы reverse proxy, согласование версий и переключение одного порта без
пользы для данных или памяти.

### Почему пересмотрено прежнее решение

В 2026-08-16 SPA была отвергнута как несоразмерная шести простым страницам.
Граница изменилась после живой проверки нескольких конфигураций: потребовались
сохранение положения, устойчивое состояние выбора, интерактивный граф,
сложные таблицы и прозрачный ход длительных заданий. Это уже подтверждённые
сценарии, а не API «на будущее». HTML остаётся рабочим fallback, но новые
интерактивные возможности в нём не дублируются.

### Покрытие кода на `/sources`

Для основной выгрузки и каждого расширения показываются три независимые
таблицы: модули и процедуры, структуры форм, модули форм. Каждая строка даёт
точное количество, долю и явный знаменатель; категории внутри таблицы
складываются в её `total`. Нулевой знаменатель отображается знаком `—`, а не
ошибкой деления или ложными `0%`.

Адресная лента первых 20 проблем с обзорной страницы убрана. Полный список
одного поколения лежит в `data/logs/code-<sha256 source_id>.json`; страница
показывает путь только после проверки sha256 и поколения. MCP, CLI и точные
причины форм в карточке объекта остаются подробными.

## Авторизация

- Чтение закрывает `API_TOKEN`, запись — `ADMIN_TOKEN`, тот же, что у
  `/admin/reload`.
- В режиме `spa` сервер перенаправляет прямую ссылку на `/login?next=...`, а
  React возвращает на проверенный внутренний путь после входа. Значение `next`
  не может быть внешним URL.
- До входа внешний `mcp_guard` пропускает точные `/health`, `/login` и
  `/assets/`. Статика нужна форме и не содержит предметных данных; `/api/v1`
  остаётся закрытым. Префикс вроде `/login-extra` доступа не получает.
- Верхняя панель показывает «Только чтение» или «Администратор», позволяет
  повысить права и завершить серверную сессию.
- **`ADMIN_TOKEN` не задан — маршруты записи отвечают 404**, на
  странице объяснено, почему загрузка недоступна.
- Сверка через `hmac.compare_digest`.
- В браузер уходит **не токен**, а случайный идентификатор сессии
  (`secrets.token_urlsafe`). Сессии — в памяти процесса, умирают с
  перезапуском; отдельного хранилища не заводим.
- Кука: `HttpOnly`, `SameSite=Strict`, `Path=/`.
- CSRF закрывается тем же `SameSite=Strict`: без него чужая страница могла бы
  отправить `POST /sources` с живой кукой. Отдельных CSRF-токенов не заводим —
  при `Strict` они избыточны.
- **Всё внешнее экранируется** через `html.escape`: имена конфигураций,
  предупреждения из манифестов, тексты ошибок, введённые фразы. Манифест делает
  чужая обработка в чужой базе — это внешние данные.

## Загрузка и индексация

- Приём `multipart/form-data`, поле `file`.
- Тип определяется по расширению **до чтения**: `.zip` → конфигурация,
  `.hbk` → справка. Прочее отвергается сразу.
- Потолок размера — **500 МБ**. Справка весит 60–70, крупная выгрузка — единицы
  мегабайт; запас десятикратный. Без потолка первый же случайный файл на
  несколько гигабайт положит контейнер по памяти.
- Файл пишется во временный, оттуда идёт в `registry.add_configuration` или
  `add_syntax`, которые сами копируют исходник в `data/sources/` и обновляют
  `registry.json`. После перезапуска источник восстановится сам.
- **Файловая подготовка и индексация уходят в пул потоков**
  (`run_in_threadpool`): событийный цикл продолжает обслуживать `/health`,
  MCP и чтение дашборда. Реестр публикует только согласованные снимки
  источников и индексов.
- После приёма браузер возвращается на `/sources`; фоновое задание сохраняет
  реестр после успешного разбора и публикует ошибку в строке задания при сбое.

Каноническая `.sqlite3` использует отдельный предел 32 МиБ и отдельный
маршрут: она не является источником Registry. Временный файл сначала проходит
полную валидацию и проверку доверия, затем атомарно заменяет управляемый файл.
Текущий неизменяемый провайдер не переключается посреди MCP-сессии; новый файл
становится активным после перезапуска. Ошибка оставляет прежний файл и
основные одиннадцать MCP-операций без изменений.

Отдельный маршрут не означает отдельную форму: на странице один выбор файла
для `.zip`, `.hbk`, `.json` и `.sqlite3`. SPA выбирает backend по расширению;
classic сохраняет тот же результат и без JavaScript через общую `/sources`.
Карточка общей справки отвечает только за `missing/untrusted/ready` и
`pending_restart`, а не дублирует upload-контролы.

Удаление управляемого файла не закрывает активный провайдер посреди MCP-сеанса:
он продолжает прежний снимок до рестарта, а затем две условные операции
исчезают. Расходный `reference.search` удаляется вместе с файлом. Внешний путь
не управляется дашбордом.

Self-restart не получает Docker socket и не выполняет shell-команду. При явно
доступном supervisor административный ответ `202` резервирует единственный
рестарт и только после отправки тела завершает процесс. `/health` публикует
случайный `runtime_id`; SPA ждёт другое значение, а не принимает первый ответ
ещё старого процесса за успешный рестарт. Без capability кнопка скрыта.

## Прогон запросов

Форма: выбор конфигурации, выбор индекса (объекты / реквизиты / справка),
многострочное поле — **одна фраза на строку**.

**Поиск по справке фильтруется по версии платформы выбранной конфигурации** —
тем же `context.syntax_filter()`, что и в `tools.py`. Иначе дашборд показывал
бы методы, которых в этой платформе нет, а весь смысл фильтрации в том, что
предупреждение человек пропустит, а отсутствующий в выдаче метод — нет. Если
конфигурация не выбрана и не загружена ни одна, справка ищется без фильтра, и
это сказано на странице.

Результат — по каждой фразе первые пять попаданий: полное имя, оценка, причина
(`точное совпадение`, `псевдоним из словаря`, `все слова запроса`, `совпала
часть слов запроса`). У найденного результата причина не бывает пустой; она
вычисляется после сортировки и не меняет оценку или порядок. Причина здесь
главное: без неё непонятно, чинить промах общим синонимом, локальным
псевдонимом, весом результата или точным адресом объекта.

Многострочный ввод — чтобы вставить десяток формулировок из живой задачи и
пройтись по ним разом.

В SPA `GET /api/v1/queries` отдаёт только контракт формы, а `POST` принимает
JSON со строковыми `config`, `scope` и списком `phrases`. Сервер валидирует
неизвестную область, максимум 32 непустые фразы и 4096 символов в каждой до
поиска. Сам прогон вызывает классический `_run_queries()`: JSON-слой ничего не
переоценивает и не сортирует повторно. Ответ содержит до пяти видимых
попаданий, до пяти скрытых версией, ссылки на карточки и, кроме `syntax`,
предзаполненный переход к псевдониму.

Конфигурация и область живут в query-параметрах прямой ссылки. Текст фраз,
последний ответ и положение страницы хранятся только в `sessionStorage`
текущей вкладки: возврат по истории восстанавливает прогон, но серверного
состояния или общей истории запросов не появляется.

## Карточки объекта и синтаксиса

Обе React-страницы используют один формат ответа: вид карточки, точное имя,
разрешённая конфигурация, список конфигураций, `brief / fields / full`,
исходный Markdown и HTML. Сервер получает текст через общую с classic UI
функцию `_card_text()`: это тот же `tools.get_object()` или
`tools.get_syntax()`, а не отдельная сокращённая модель для браузера. HTML
строит прежний `render_markdown()`, который сначала экранирует внешние данные;
frontend не разбирает Markdown и не добавляет второй набор правил.

Имя, конфигурация и подробность остаются в URL. «Как есть» показывает уже
полученный Markdown и тоже фиксируется параметром `raw=1`, поэтому
переключение не выполняет карточку повторно. Пустой `/object` или `/syntax`
объясняет, что точный адрес берётся из «Запросов»; предметные ошибки Registry
возвращаются как `409`. Для объекта конфигурация обязательна и единственная
разрешается прежним `Registry.resolve()`. Синтаксис может работать совсем без
конфигурации — без фильтра по версии, если подключена справка платформы.

## Граф связей

React-страница получает `config`, точное `name` и `limit` через
`GET /api/v1/graph`. Если адрес открыт из меню без параметров, сервер выбирает
первую конфигурацию и интерфейс закрепляет её в URL; отсутствие имени —
нормальное состояние формы, а не ошибка Registry. Для неизвестного имени API
возвращает до пяти предложений из того же индекса объектов. Пустой Registry и
объект без связей имеют отдельные объяснённые состояния.

JSON-слой вызывает общий `graph_view.neighbourhood()` и не повторяет отбор или
раскладку. В ответе уже лежат координаты узлов, границы `viewBox`, общее и
показанное число соседей, степени, цвета видов, направления и подписи рёбер.
Глубина всегда один шаг; допустимые варианты интерфейса — 15 / 30 / 60 / 150 /
400, произвольный прямой параметр ограничивается прежним диапазоном 1…400.
Усечение называется явно и сохраняет прежний порядок: сначала соседи с
большей общей степенью.

Frontend рисует готовые координаты обычным SVG. Перетаскивание и колесо меняют
только `viewBox`, кнопка возвращает серверные границы, а клик по узлу открывает
тот же маршрут с новым центром. Направление и подпись продублированы в боковом
списке, поэтому смысл связи не зависит от hover. Отдельная библиотека графа не
добавлена: кольцевая раскладка предметно задана в Python и уже общая для
classic и SPA.

## Словарь поиска

`GET /api/v1/dictionary` возвращает правила, эффективные для выбранной
конфигурации. Для каждого псевдонима ответ содержит нормализованную фразу,
полные имена целей, происхождение, точную область (`*`, имя конфигурации или
`null` для встроенного слоя) и признак возможности удаления. Встроенные
группы синонимов раскрываются только числом, как в classic UI; локальные
приходят полным составом и могут быть сняты.

Добавление и удаление разделены на четыре явных POST-маршрута для псевдонимов
и синонимов. Они используют общий с classic UI
`Registry.mutate_dictionary()`, поэтому сохраняют файл атомарно и не создают
вторую модель словаря. Запись требует администратора и same-origin при
cookie-сессии; токен чтения получает только снимок. Локальный псевдоним
снимается из переданной точной области, не затрагивая одноимённый нижний слой.

Конфигурация живёт в URL. Переход из результата «Запросов» добавляет туда и
`phrase`, редактор подставляет её и по умолчанию выбирает текущую
конфигурацию. При прямом входе из меню выбирается первая конфигурация, а при
пустом Registry остаются доступны встроенные и общие локальные правила.
Правка действует в новых запросах сразу: словарь применяется во время поиска,
а не при построении индекса.

## Ошибки

| Что | Поведение |
|---|---|
| `ExportError`, `RegistryError` | ошибка в задании, готовое состояние реестра не подменяется |
| Файл не того расширения | отказ до чтения содержимого |
| Файл больше потолка | отказ, понятное сообщение |
| Нет токена в сессии | 403 на записи, форма входа на странице |
| `ADMIN_TOKEN` не задан | маршруты записи 404 |
| Конфигурация не выбрана на `/queries` | подставляется единственная; если их несколько — просим выбрать явно, как это делает `resolve()` |

## Правило изменений

Дашборд — **инструмент проверки, а не продукт**. Изменение в нём оправдывается
тем, что сокращает цикл «спросил → понял почему → починил». Если делает
красивее при той же скорости понимания — это украшение, и мы его не делаем.

По этому правилу уже сделанное: колонка «почему» (без неё непонятно, чем лечить
промах), оценка числом (виден разрыв, то есть уверенность), ссылка на карточку
(иначе идёшь спрашивать агента), моноширинный текст (выравнивание сохраняет
читаемость списков). Не заводим: тем, шрифтов, иконок, анимаций, графиков,
сортировки колонок, пагинации.

## Риски

- **Загрузка и разбор выполняются в фоне.** Страница показывает состояние
  задания, а `/sources` — атомарное состояние источника и индекса кода;
  долгие файловые операции не выполняются в событийном цикле.
- **Сессии в памяти.** Перезапуск сервера разлогинивает. Приемлемо: вход — это
  одно поле и одна вставка токена.
- **Один процесс.** Тяжёлая индексация занимает поток из пула; при нескольких
  одновременных загрузках они встанут в очередь. Загрузка — редкая операция,
  очередь допустима.
