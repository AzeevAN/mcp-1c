# Создание метаданных 1С

Версия: `0.1.0-candidate`.

Локальный компилятор создаёт owner-relative файлы в отдельном каталоге. Установи рядом `1c-form-creator`: его локальное ядро проверяет формы в комплекте. MCP-сервер для работы скриптов не нужен.

## Порядок

1. Прочитай `references/workflow.md` и возьми формат XML из целевой `Configuration.xml`. Уточни вид, имя, свойства и конкретный ожидаемый сценарий объекта. Для создания формы прочитай также `1c-form-creator/SKILL.md`.
   «Основная форма справочника» для просмотра или редактирования одной записи
   означает `role=object`, `default=true`, `DefaultObjectForm` и поля
   `Объект.Code`, `Объект.Description`, `Объект.<Реквизит>`.
   `role=list`/`DefaultListForm` означает таблицу всех записей и не заменяет
   форму одного элемента.
2. Составь metadata specification schema v1. Для объекта без формы задай `"forms": []`. Для объекта с формой сначала собери и проверь её локальным `form_creator.py` **без `--config`**. Передай **точные** файлы `Form.xml` и итоговый `Module.bsl` через `form_xml_file` и `module_bsl_file`. Пустой каркас модуля нужен лишь как вход; в выходной комплект он не входит. Не сочиняй XML вручную.
3. Запусти `scripts/metadata_creator.py build` в новый пустой каталог. Сравни каждый файл и патч `Configuration.xml` с целевой выгрузкой до применения. Исходная конфигурация скриптом не меняется.
4. Повтори `validate` на собранном комплекте. Сверь BSL API со справкой версии платформы и выполни нативный импорт, открытие формы и сценарий в 1С. Записывай результаты отдельно: `static_passed` не подтверждает работу BSL или открытие формы.

```bash
python3 SKILL_DIR/scripts/metadata_creator.py inspect --config CONFIG_DIR
python3 SKILL_DIR/scripts/metadata_creator.py build --spec metadata.json --config CONFIG_DIR --output EMPTY_STAGING_DIR
python3 SKILL_DIR/scripts/metadata_creator.py validate --bundle EMPTY_STAGING_DIR --object-ref Справочник.Имя --format-version 2.20
```

`--config` при `build` сверяет версию и создаёт копию `Configuration.xml` с точечной регистрацией и `.patch`; без него собираются только файлы владельца. Путь к форме в JSON считается относительно `metadata.json`. Скрипт пишет BOM и CRLF для XML/BSL, проверяет owner-relative пути и отклоняет непустой каталог результата. Выход 2 означает ошибку.

## Граница проверки

`verification.json` содержит `metadata_check` и независимые статусы `bsl_api`, `native_import`, `runtime_visual`, `business_behavior`; последние остаются `not_checked` до фактической проверки. Для формы проверяй также результат `form_creator.py validate`. Если компилятор не поддерживает нужную структуру или exact round-trip существующего файла невозможен, остановись с точной причиной и используй нативный редактор 1С. Не применяй частичный комплект.

Комплект предназначен для файловой выгрузки и не изменяет тестовую базу напрямую. Для установки скопируй каталоги `1c-metadata-creator` и `1c-form-creator` рядом в каталог skills клиента.
