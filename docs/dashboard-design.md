# Дашборд: спецификация

Согласовано 2026-08-16. Реализация ведётся по этой спеке; расхождения
правятся здесь, а не в коде молча.

## Зачем

Сейчас источник добавляется командой внутри контейнера:

```bash
docker compose exec mcp1c python -m mcp1c.cli reg-add /data/bootstrap/Выгрузка.zip --data /data
```

Это работает, но требует доступа к контейнеру и знания CLI. Дашборд закрывает
две вещи: **положить выгрузку через браузер** и **посмотреть, что сервер
отвечает на живую формулировку**, не поднимая консоль.

## Границы первой версии

Входит:

- реестр загруженного с предупреждениями из манифестов;
- загрузка `.zip` и `.hbk` через браузер, удаление источника;
- прогон списка запросов с показом оценок и причин.

Не входит и вынесено в «Дальше»:

- правка словаря через браузер — механизм готов (`dict-*`), нужен интерфейс;
- статус фоновой индексации — в первой версии загрузка синхронная, браузер ждёт;
- кнопка «записать промах в `tests/queries/`» — она пишет в репозиторий, а не в
  `data/`, и на сервере репозитория может не быть вовсе. Отдельное решение.

Ожидаемый ответ рядом с запросом (как в `bench.py`) **сознательно не делаем**:
на десятке фраз попадание видно глазами, а массовый прогон с метриками уже
закрыт стендом из CLI. Дублировать его в браузере нечем оправдать.

## Архитектура

```
server.py      монтирует маршруты дашборда — как уже монтирует /health
dashboard.py   НОВЫЙ: маршруты, разметка, сессии. Знает Registry, не знает MCP
registry.py    без изменений
tools.py       без изменений
```

`dashboard.py` отдаёт список маршрутов, а не приложение:

```python
def routes(registry: Registry) -> list[Route]: ...
```

Тот же приём, что уже применён к `tools.py`: предметный слой не знает про MCP,
дашборд не знает про MCP-сервер. Тесты вешают маршруты на голый `Starlette` и
не тянут SDK.

Зависимостей не добавляется: `starlette` приходит с `mcp`, остальное — stdlib.

### Один процесс с MCP

Дашборд меняет состояние живого сервера: добавленная конфигурация обязана стать
доступной агенту немедленно. Отдельный процесс писал бы в `data/`, а сервер
продолжал держать в памяти старое — понадобился бы `/admin/reload` с повторным
подъёмом реестра, а это секунда работы и лишний шаг для человека.

### Один порт с MCP

Второй порт имел бы смысл, чтобы закрыть интерфейс фаерволом отдельно. Но
чтение открыто сознательно, а запись под токеном, поэтому второй порт даёт
только лишнюю настройку в `docker-compose.yml`. Понадобится — вынесем, маршруты
от этого не изменятся.

### Серверный HTML без сборки

Страницы собираются строками в Python, формы обычные, JS — только индикатор
ожидания. Ноль шагов сборки, образ не растёт, дашборд работает с выключенным JS.

Отвергнуто: SPA на React (npm в образ или собранные артефакты в git —
несоразмерно четырём экранам) и JSON API с отрисовкой на клиенте (API «на
будущее» при единственном потребителе — то, чего проект избегает).

## Страницы и маршруты

| Маршрут | Что делает | Доступ |
|---|---|---|
| `GET /` | обзор: что загружено, объекты, версия платформы, предупреждения | открыто |
| `GET /sources` | управление: форма загрузки и удаление источников | открыто |
| `POST /sources` | приём файла, индексация, редирект на `/sources` | токен |
| `POST /sources/remove` | удалить источник из реестра | токен |
| `GET /queries` | форма прогона запросов | открыто |
| `POST /queries` | прогон, та же страница с результатами | открыто |
| `POST /login` | принять токен, выдать сессионную куку | — |
| `POST /logout` | сбросить сессию | — |

Существующие `/health` и `/mcp` не трогаются.

Реестр берётся из готового `registry.overview()`: имя, версия, платформа,
объекты, рёбра, соотношение версий справки, сколько элементов скрыто фильтром и
`notes()` с предупреждениями. Дашборд их только рисует.

## Авторизация

- Токен — `ADMIN_TOKEN` из окружения, тот же, что у `/admin/reload`.
- **Токен не задан — маршруты записи отсутствуют** (404, как у `reload`), на
  странице объяснено, почему загрузка недоступна.
- Сверка через `hmac.compare_digest`.
- В браузер уходит **не токен**, а случайный идентификатор сессии
  (`secrets.token_urlsafe`). Сессии — в памяти процесса, умирают с
  перезапуском; отдельного хранилища не заводим.
- Кука: `HttpOnly`, `SameSite=Strict`, `Path=/`.
- CSRF закрывается тем же `SameSite=Strict`: без него чужая страница могла бы
  отправить `POST /sources` с живой кукой. Отдельных CSRF-токенов не заводим —
  при `Strict` они избыточны.
- **Всё внешнее экранируется** через `html.escape`: имена конфигураций,
  предупреждения из манифестов, тексты ошибок, введённые фразы. Манифест делает
  чужая обработка в чужой базе — это внешние данные.

## Загрузка и индексация

- Приём `multipart/form-data`, поле `file`.
- Тип определяется по расширению **до чтения**: `.zip` → конфигурация,
  `.hbk` → справка. Прочее отвергается сразу.
- Потолок размера — **500 МБ**. Справка весит 60–70, крупная выгрузка — единицы
  мегабайт; запас десятикратный. Без потолка первый же случайный файл на
  несколько гигабайт положит контейнер по памяти.
- Файл пишется во временный, оттуда идёт в `registry.add_configuration` или
  `add_syntax`, которые сами копируют исходник в `data/sources/` и обновляют
  `registry.json`. После перезапуска источник восстановится сам.
- **Индексация уходит в поток** (`run_in_threadpool`): разбор `.hbk` — около
  4 секунд, и в событийном цикле это остановило бы и MCP-клиентов. Реестр к
  этому готов: индексы строятся до подмены, состояние меняется под `RLock`.
- После успеха — `registry.save()` и редирект на `/sources`.

## Прогон запросов

Форма: выбор конфигурации, выбор индекса (объекты / реквизиты / справка),
многострочное поле — **одна фраза на строку**.

**Поиск по справке фильтруется по версии платформы выбранной конфигурации** —
тем же `context.syntax_filter()`, что и в `tools.py`. Иначе дашборд показывал
бы методы, которых в этой платформе нет, а весь смысл фильтрации в том, что
предупреждение человек пропустит, а отсутствующий в выдаче метод — нет. Если
конфигурация не выбрана и не загружена ни одна, справка ищется без фильтра, и
это сказано на странице.

Результат — по каждой фразе первые пять попаданий: полное имя, оценка, причина
(`точное совпадение`, `псевдоним из словаря`, `все слова запроса`). Причина
здесь главное: без неё непонятно, чинить синонимом, псевдонимом или весом —
ровно те четыре случая, что перечислены в «Практиках» доски задач.

Многострочный ввод — чтобы вставить десяток формулировок из живой задачи и
пройтись по ним разом.

## Ошибки

| Что | Поведение |
|---|---|
| `ExportError`, `RegistryError` | текст на странице, состояние сервера не изменилось |
| Файл не того расширения | отказ до чтения содержимого |
| Файл больше потолка | отказ, понятное сообщение |
| Нет токена в сессии | 403 на записи, форма входа на странице |
| `ADMIN_TOKEN` не задан | маршруты записи 404 |
| Конфигурация не выбрана на `/queries` | подставляется единственная; если их несколько — просим выбрать явно, как это делает `resolve()` |

## Тесты

`pytest`, маршруты на голом `Starlette` через `TestClient`, фикстуры из
`conftest.py` — синтетическая выгрузка и справка, от содержимого `data/`
тесты не зависят.

| Тест | Что доказывает |
|---|---|
| реестр показывает источники и предупреждения | страница читает `overview()` |
| загрузка без токена → 403, реестр прежний | запись закрыта |
| загрузка с токеном → источник в реестре | сквозной путь |
| `ADMIN_TOKEN` не задан → запись 404 | по умолчанию закрыто |
| битый файл → ошибка на странице, реестр прежний | сбой не ломает сервер |
| файл чужого расширения → отказ | тип проверяется до чтения |
| удаление источника уносит его из реестра | и кэш заодно |
| прогон возвращает попадания с причиной | страница прогона |
| имя конфигурации с `<script>` экранируется | XSS через манифест |
| неверный токен → сессия не выдана | сравнение работает |

## Правило изменений

Дашборд — **инструмент проверки, а не продукт**. Изменение в нём оправдывается
тем, что сокращает цикл «спросил → понял почему → починил». Если делает
красивее при той же скорости понимания — это украшение, и мы его не делаем.

По этому правилу уже сделанное: колонка «почему» (без неё непонятно, чем лечить
промах), оценка числом (виден разрыв, то есть уверенность), ссылка на карточку
(иначе идёшь спрашивать агента), моноширинный текст (выравнивание сохраняет
читаемость списков). Не заводим: тем, шрифтов, иконок, анимаций, графиков,
сортировки колонок, пагинации.

## Риски

- **Загрузка блокирует браузер на секунды.** Осознанно: статус фоновой
  индексации отложен. Если ожидание окажется неприемлемым, добавляем статус
  отдельной задачей, маршруты при этом не меняются.
- **Сессии в памяти.** Перезапуск сервера разлогинивает. Приемлемо: вход — это
  одно поле и одна вставка токена.
- **Один процесс.** Тяжёлая индексация занимает поток из пула; при нескольких
  одновременных загрузках они встанут в очередь. Загрузка — редкая операция,
  очередь допустима.
